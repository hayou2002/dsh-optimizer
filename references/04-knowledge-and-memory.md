# 知识与规则的整理

DSH 没有上游 Agent 式的原生 `/memories` 控制面，也没有可写回的记忆接口。长期知识由三类载体承担：全局指令文件、技能、项目文档。整理知识就是整理这三类文件。

## 说明

- `$DSH_HOME/AGENTS.md`：用户级长期约定，随每个会话加载。可能同时存在 `~/.agents/AGENTS.md`。
- 项目级 `AGENTS.md`：从项目根到会话 cwd 逐层加载的指令链。
- `$DSH_HOME/skills/`、`<项目>/.dsh/skills/`、`~/.agents/skills/`：可执行知识与参考。
- 定时任务的 prompt 与既有任务：长期运行的巡检与整理约定。
- 项目 `README.md` / `source.md`：项目身份、来源与交付说明。

DSH 主目录是生成状态，不是知识库。除非用户明确要求，不要改 `$DSH_HOME` 下的会话、附件、存储与凭据。整理知识与规则的入口是显式文件，不是运行时状态。

## 什么时候动

- 用户说「知识太乱」「规则过时」「整理一下约定」。
- 新发现与既有约定冲突，且冲突会影响后续执行。
- 同一事实在多个文件里各写一份，且已经漂移。

不要把知识整理当成清理磁盘的副产物；它只在被要求或确有冲突时发生。

## 审计清单

1. 载体清单：每个候选文件的路径、大小、条目数、mtime、hash。
2. 完全重复：字节级相同的段落或文件。
3. 冲突候选：同一主题的互斥结论，标出各自出处。
4. 失效路径：引用了已不存在的文件、目录或命令。
5. 少用信号：长期未被任何指令引用的孤岛文件。
6. 多源漂移：同一规则在不同载体的多个版本。

## 支持的整理操作

去重、合并、压缩、拆分、降权、退役、删除、消冲突、类目修复、格式修复。

- 自动执行仅限：字节级完全重复的合并、格式规范化、已证失效路径的清理。
- 其余（压缩、语义合并、冲突裁决、删除）先展示差异与影响面，得到确认再动。
- 冲突与过时的处理顺序：新现场 > 旧文档；显式用户约定 > skill 默认；可验证事实 > 推测。

## 直改文件流程

1. 先记录 path / size / mtime / hash。
2. 事务内留原始副本或一条恢复记录，放 `_temp/checkpoints/`。
3. 临时文件写入后原子替换，避免半截文件。
4. 变更写进批次 `manifest.jsonl`。
5. 下次运行发现 hash 与记录不符（被别的进程重写）时只报告，不静默覆盖。

## 知识分层

- 需长期生效、每次会话都要看的约定 → `AGENTS.md`（全局或项目级）。
- 需要可执行步骤与脚本 → 技能目录。
- 项目范围内的身份、来源、交付 → 项目 `README.md` / `source.md`。
- 一次性的经验与临时召回 → 会话本身，不进长期载体；确需留存时由用户点名落到哪个文件。
